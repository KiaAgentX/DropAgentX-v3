# ADR-007 — Dashboard as a Vite React SPA (no SSR)

- Status: accepted (Phase 4)
- Date: 2026-11-05
- Owner: DropAgentX v3

## Context

فاز ۴ یک پنل ادمین می‌سازد: ترازها، تراکنش‌ها، صف HITL، محصولات، پارلمان.
گزینه‌ها: Next.js (همان استک دموی فضای کاری)، یا یک SPA سبک. محدودیت‌های معیار پذیرش:

- Lighthouse موبایل ≥ ۹۰
- RTL بدون شکستگی (fa پیش‌فرض، en اختیاری)
- «خروجی از قرارداد OpenAPI فاز ۲» — کلاینت تایپ‌دار همان `@dropagentx/contracts`
- فاز ۶: Railway **سرویس واحد** — سرور Fastify و بات در یک پروسه؛ داشبورد هم باید در همان سرویس جا شود

## Decision

`apps/dashboard` یک **Vite + React 19 + Tailwind v4 SPA** است:

1. **بدون SSR** — پنل ادمین هیچ نیاز SEO/سرور-رندر ندارد؛ SPA کوچک‌ترین باندل و ساده‌ترین عملیات را می‌دهد.
2. **Hash routing بدون وابستگی router** — استقرار به‌صورت فایل‌های استاتیک کنار Fastify (فاز ۶) بدون هیچ rewrite rule؛ روی موبایل هم مسیرها بی‌وقفه کار می‌کنند.
3. **i18n خودنویس** (دو دیکشنری flat با برابری کلیدی در سطح نوع و تست) — به‌جای کتابخانه‌ی i18n؛ دو زبان یعنی هزینه‌ی کتابخانه توجیه ندارد.
4. **کلاینت = `createV3Client`** از contracts با یک لایه‌ی نازک فقط برای تزریق `X-KIA-Key`؛ اعتبارسنجی پاسخ‌ها همچنان با zod همان اسکیمای سرور (حلقه‌ی ADR-005 از سمت داشبورد بسته شد — تست roundtrip با `app.inject`).
5. **کلید مدیریت فقط در `sessionStorage`** — با بستن تب می‌میرد؛ فقط در هدر `X-KIA-Key` سفر می‌کند؛ هیچ کلیدی در localStorage یا بدنه‌ی درخواست‌ها نیست.

## Consequences

- `dist/` داشبورد در فاز ۶ با `@fastify/static` سرو می‌شود (یک سرویس، یک دیپلوی، دامنه‌ی واحد → CORS هم حذف می‌شود).
- اگر بعداً صفحات عمومی مارکتینگ (SEO) لازم شد، آن‌ها را جدا می‌سازیم — این تصمیم مانع آن نیست.
- هزینه‌ی باندل: zod + React (~۱۱۲KB gzip) — برای پنل ادمین قابل‌قبول؛ اگر سختگیرانه شد، تقسیم باندل در فاز ۶.
