# ADR-003 — دفتر دوطرفه تغییرناپذیر

- **وضعیت**: پذیرفته‌شده
- **تاریخ**: ۱۴۰۵ آبان

## زمینه
ممیزی لجسی نشان داد ۹ خرید ۵۰-اعتباری «تراز را کم کرده بودند بدون ثبت تراکنش» و یک اعتبار دستی
مالک +۳۸۷ بدون ردیف بود — یعنی v2 ستون balance و جدول تراکنش را جدا نگه می‌داشت و بين‌شان شکاف می‌افتاد.

## تصمیم
تراز هر حساب **مشتق** است، نه ذخیره‌شده: تنها منبع حقیقت جدول `Postings` است و هر `Transaction`
حداقل ۲ ردیف با مجموع صفر دارد. قوانین جهت (fail-closed):

| حساب | قانون |
|---|---|
| user / escrow / treasury | تراز هرگز منفی نمی‌شود |
| mint | تراز هرگز مثبت نمی‌شود (فقط صادر می‌کند) |
| burn | تراز هرگز منفی نمی‌شود (فقط دریافت می‌کند) |

Idempotency key اختیاری است: post دوم با همان key = replay بی‌اثر با همان تراکنش اصلی.
پایایی (conservation) مقدس است: Σ تراز همه‌ی حساب‌ها همیشه صفر.

## پیامدها
- ✅ گپ لجسی (−۶۳ Đ) در معماری جدید از جنس «نقض invariant» است و ساختمانِ آن بسته شده.
- ✅ ممیزی هر لحظه ممکن است: `trialBalance(state).balanced`.
- ✅ تلاش مجدد webhook/شبکه دوبار پول جابه‌جا نمی‌کند.
- ❌ درج تراکنش ۲ ردیف دارد — هزینه‌ی ذخیره‌سازی ناچیز و پذیرفتنی.
