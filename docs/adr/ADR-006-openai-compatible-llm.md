# ADR-006 — لایه‌ی LLM سازگار با OpenAI (سه متغیر محیطی)

- **وضعیت**: پذیرفته‌شده — به انتخاب صریح مالک پروژه
- **تاریخ**: ۱۴۰۵ آبان

## زمینه

فاز ۵ (چرخه‌ی AI) به یک لایه‌ی مدل نیاز دارد؛ اما از همین فاز ۲ باید قرارداد سیمی قفل شود تا
قراردادها و کانفیگ از روز اول با آن ساخته شوند. هرمس به‌خاطر پیوند با 9router چند SDK و چند
شکل پاسخ موازی داشت — همان چندگانگی که نگه‌داری را پرهزینه کرد. اکوسیستم امروز یک استاندارد
عملی دارد: مسیر `POST /chat/completions` با احراز `Bearer`.

## تصمیم

**تنها یک قرارداد سیمی برای همه‌ی مدل‌ها: API سازگار با OpenAI.**
سه متغیر محیطی و هیچ چیز دیگری:

| متغیر | نقش | مثال |
|---|---|---|
| `OPENAI_BASE_URL` | مبنای سرویس‌دهنده | `https://api.provider.com/v1` |
| `OPENAI_API_KEY` | اعتبار Bearer | `sk-…` |
| `MODEL` | نام مدل در بدنه‌ی درخواست | `glm-4.7` |

پیاده‌سازی در `packages/llm`:

- بدون SDK شخص ثالث — `fetch` خالص Node، صفر وابستگی runtime به‌جز zod برای اعتبارسنجی پاسخ.
- خطاها **Result** تایپ‌دار: `NETWORK / TIMEOUT / PROVIDER_AUTH / RATE_LIMITED / PROVIDER_ERROR / MALFORMED_RESPONSE`.
- تایم‌اوت واقعی با `AbortController` — سرویس‌دهنده‌ی معلق نمی‌تواند ربات را بخواباند.
- **fail-closed**: سه متغیر با هم یا هیچ‌کدام؛ کانفیگ ناقص خطای راه‌اندازی است، نه fallback خاموش.
- کلید API هرگز در پیام خطا، لاگ یا تست ظاهر نمی‌شود (فقط hint ماسک‌شده).
- `/models` به‌عنوان پروب ارزان سلامت سرویس‌دهنده.

## پیامدها

- ✅ تعویض مدل یا سرویس‌دهنده = تغییر سه متغیر محیطی، نه یک خط کد.
- ✅ fallback چندسرویس‌دهنده‌ی فاز ۵ = چند `LlmConfig` با همین شکل؛ primary → secondary قطعی و قابل‌تست.
- ✅ مصرف per-user و ممیزی فاز ۵ روی یک سطح پاسخ ثابت سوار می‌شود.
- ✅ تست بدون شبکه واقعی: سرور mock سازگار با OpenAI در خود بسته.
- ❌ قابلیت‌های vendor-specific (استریم، tool-calls، logprobs) فعلاً پشتیبانی نمی‌شود —
  در فاز ۵ به‌صورت additive روی همین قرارداد اضافه می‌شود؛ کدهای خطا فقط بزرگ می‌شوند، نمی‌شکنند.
